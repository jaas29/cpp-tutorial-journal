Plan for a long day, two days out from the meeting

Where I actually am, measured not guessed

Five days since the last commit. Before planning anything, the honest question is what the repository does today, so the first thing run this morning was the working tree as it stands:

$ cmake --build build/dev
[100%] Built target tests

$ ./build/dev/tests
EXIT=133

No output at all. Not one line of the five size/cap prints, even though they run before anything goes wrong. This is exactly the failure recorded in record 0007: the process dies on SIGTRAP before stdout is flushed, so the program's own output disappears along with the crash.

The cause is visible in the diff. include/containers/vector.hpp has a copy constructor now, uncommitted. It has no copy assignment operator — and tests/main.cpp, also uncommitted, already contains c = a;. So the compiler supplies the assignment, member by member, copying the pointer. Two objects, one buffer, two destructors. The double free from Lesson 6 is back, through the other door.

So I am not behind on understanding. I am behind on finishing. Lessons 1–7 and eight learning records are done and hold up. The repo is one function short of the thing they describe, and that one function is the whole reason today's build is red.

What Wednesday actually needs

The meeting is not a quiz. It is a code review, and the mission says what it is judged on: ownership and lifetime decisions, defended out loud, with measurements rather than vibes. That reframes the day. The winning position on Wednesday is a finished, measured Vector — not a half-started unordered_map next to a broken one.

unordered_map is explicitly not today's work. Attempting it would produce two unfinished containers instead of one finished one, and nothing to defend.

The blocks

Six working blocks, about six hours, with the breaks written in because they are the part that gets skipped. Each block ends in a commit or a recorded measurement — something that survives being interrupted.

Block 1Close the copy — 45 min

Write Vector &operator=(const Vector &other) in include/containers/vector.hpp. Use the ordering established in record 0008 — allocate, copy, then release — and keep the self-assignment guard, remembering that on this ordering it is an optimization and not the correctness fix, which is the point worth being able to say out loud on Wednesday.

$ cmake --build build/dev && ./build/dev/tests
# expect: five size/cap lines, then a[0] = 0  b[0] = 999,
#         then c[0] = 0, then after self-assign c[3] = 30

Green means commit, right then. Ownership sheet section 3 has the signature.

Block 2Prove it under all three builds — 60 min

One green build is not a clean container. Records 0005, 0006 and 0007 established that no single configuration sees everything. Run all three and write down the output verbatim:

$ cmake --build build/dev   && ./build/dev/tests     # UBSan
$ cmake --preset asan && cmake --build build/asan
$ ./build/asan/tests                                     # heap errors
$ clang++ -std=c++20 -g -Iinclude tests/main.cpp -o /tmp/leakcheck
$ leaks --atExit -- /tmp/leakcheck                        # leaks only

"0 leaks for 0 total leaked bytes" plus a clean ASan run is the sentence the deliverable is actually claiming. Paste all three into the journal entry tonight — that transcript is the strongest single thing to bring to the meeting.

Break — 15 min. Away from the screen.

Block 3Move semantics — 90 min

The largest remaining gap between this Vector and one a working engineer reads as current. Copy is correct now but pays for a buffer it does not need when the source is about to die. Move constructor and move assignment: steal the pointer, null the source, and the destructor that follows becomes a no-op.

Ask for Lesson 8 at the start of this block — it is not written yet, and it should be written against the copy assignment committed in Block 1 rather than in advance of it.

Break — 20 min. Lunch.

Block 4Make it a template — 75 min

Vector becomes Vector<T>. The library is already header-only (record 0002), so this is mostly mechanical — but it reopens the question record 0008 left open on purpose: whether the allocate-copy-release ordering still holds when T has a non-trivial copy assignment of its own. Test it with a T that is itself a Vector<int>. If the answer differs, that is a ninth learning record and a genuinely good thing to walk into a review holding.

Block 5Assertions, not eyeballs — 60 min

Every check in tests/main.cpp today is a cout line read by a human. Record 0008 found the case that makes this untenable: reading uninitialized memory is invisible to all three build configurations, so the only possible detector is a test that fails loudly. Wire up GoogleTest — the CMakeLists.txt comment already reserves the spot — or, if that fights back, a twenty-line CHECK macro that returns non-zero. Either beats reading numbers off a terminal.

Block 6Write the meeting one-pager — 45 min

Four headings, no more. What shipped. What I measured (the three transcripts from Block 2). The three blind spots I found in my own toolchain — leaks, silent aborts, uninitialized reads — which is the most interesting thing produced in four weeks and should not be left to come up by accident. What is next and when: unordered_map, with a date.

If the day runs short

Blocks 1, 2 and 6 are the ones that must happen. A committed, measured, documented Vector with copy semantics is a defensible deliverable on its own. Blocks 3–5 make it a better one. Cutting from the middle is fine; arriving Wednesday with the tree at exit 133 is not.

Anything unclear in any block — the assignment signature, why the move constructor needs noexcept, how to wire GoogleTest — ask. That is what the teacher is for, and asking mid-block is faster than being stuck in one.

How the day actually went

Added 8 September, the morning after. The above is a plan; this is what came of it.

Blocks 1 through 4 landed, in three commits: c47e13a copy constructor and copy assignment, fd314e0 the two move operations completing the Rule of Five, and b5e28ea the template. Block 2's three-configuration run came back clean and is the transcript I am taking to the meeting — dev and asan both exit 0, leaks reports 0 leaks for 0 total leaked bytes.

Block 4 produced the ninth learning record, though not the one it predicted. The allocate-copy-release ordering did hold once T had a copy assignment of its own, which closed the question record 0008 left open. The record came from somewhere else entirely: templating exposed a grow() that deep-copied every element and then destroyed the originals on the next line, a bug written in Lesson 5 that no Vector<int> test could ever have caught, because moving an int is copying an int. Fifty-one allocations down to forty-four. Record 0009.

Block 5 did not happen, and not because the day ran out. I decided GoogleTest was not important enough to spend the time on. The property missing from tests/main.cpp is a nonzero exit code when a check is wrong — that is the whole finding from record 0008. A framework supplies that property, but it also brings FetchContent, a pinned tag, a rename of the test file and a minute of build time per preset, and none of that is the part I need. Block 5's own fallback above said as much. A ten-line CHECK_EQ macro buys the same property in an afternoon, and the days it saves go to unordered_map, which is the actual gap against the four-week plan. Moved to 10 September.

Block 6, the checkpoint one-pager, is written and stays out of this repo. Still open going into Wednesday: Vector has no const operator[], so a const Vector<T>& cannot be indexed at all — the first thing a reviewer would hit.
