An undefined symbol that never named the guilty file

Built

Started mystl, the scratch repo where I follow along with The Cherno's videos outside the lesson track. Nothing here is graded; the point is to break things on purpose and see what the errors look like.

What broke

I split a Log function out of main.cpp into its own src/Log.cpp, which is the obvious tidy-up, and the build failed at link time:

Undefined symbols for architecture arm64:
  "Log(char const*)", referenced from:
      ltmp1 in main.cpp.o

What made this hard is that the error names main.cpp.o, the file that is correct, and never mentions Log.cpp at all. I spent a while staring at main.cpp looking for a typo that was not there.

What I took away

Putting a .cpp in src/ does not put it in the build. Nothing in the toolchain scans directories. add_executable is the only statement of which translation units exist, and Log.cpp was not in it — so it was never compiled, produced no object file, and supplied no symbol. Meanwhile main.cpp compiled perfectly happily, because my hand-written declaration void Log(const char*); was all the compiler ever needed to see. The compiler trusts the declaration; only the linker checks whether anyone actually wrote the thing.

We diagnosed it by reading the symbol tables rather than guessing, which is the part I want to remember. Written up as learning record 0003.
