The heap, a Vector, and a leak two builds could not see

Built

The first code in this project that is actually Project 1 — a growable int buffer with doubling reallocation, committed to p1-containers. About forty lines. It contains a memory leak, on purpose, which the next lessons exist to fix.

Three lessons on the build system was enough.

Worked through

  • Lesson 5 — The Heap, and Your First Vector. Stack versus heap: the stack is where the compiler already knows the size at compile time, and leaving a function throws it all away; the heap is what you ask for at runtime when you do not know the size yet. That difference is the entire reason vector has to exist.
  • Wrote the vector-internals sheet — size versus capacity, growth, reallocation, and which of those invalidates an iterator.
  • Did the weeks 1–2 recall quiz, to find out what had actually stuck rather than what I recognised.

Paired video

Lesson 5 pairs with The Cherno's Stack vs Heap Memory in C++, POINTERS in C++, and The NEW Keyword in C++ — he draws what is happening in memory rather than describing it, which is how I follow this best. What I have actually watched and when is tracked in the video log.

Standing caveat on all of it: video is for intuition, learncpp is for style. He uses raw new and delete throughout. Inside Project 1 that is fine and correct — writing a container means I am the one doing the manual memory. It does not carry into P2 or P3.

What broke

I verified Lesson 5 against the real Project 1 repo rather than a scratch build, and the leak disappeared. Same source, same compiler, only the flags different:

<no extra flags>                              -> 1 leak for 48 total
-fno-omit-frame-pointer                       -> 1 leak for 48 total
-fsanitize=undefined                          -> 0 leaks for 0 total
-fno-omit-frame-pointer -fsanitize=undefined  -> 0 leaks for 0 total

-fsanitize=undefined alone flips it. That is exactly what my dev preset turns on, which means neither of my two presets can find a leak: the asan one because LeakSanitizer does not exist on Darwin (yesterday's finding), and the dev one because UBSan's instrumentation hides the allocation from Apple's leaks. Two different causes, same silence.

What I took away

A clean sanitizer run is only evidence for the things that sanitizer actually checks on this platform. I now check leaks with a third, unflagged build rather than assuming the presets cover it. Recorded as learning record 0006.
