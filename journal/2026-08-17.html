Four programs behind one command

Built

First working session of the tutorial. Nothing to build yet, so the work was getting the machine into a state where building is trustworthy.

Worked through

  • Lesson 1 — Four Programs, Not One. The thing I did not know: clang++ main.cpp is not one program. It is a preprocessor, a compiler, an assembler, and a linker run in sequence, and almost every error message I will get for the next four months is really telling me which of the four stopped.
  • Started the glossary, which I add to as terms actually come up rather than filling in ahead of time.

What broke

The whole afternoon, in the end. I built a program with -fsanitize=address and it compiled, linked, and then hung on startup with no output at all. No crash, no error, nothing to search for.

We sampled the stuck process instead of guessing, and the stack showed AddressSanitizer deadlocking inside its own initialisation: its shadow-memory setup calls into macOS 26's dyld, which calls malloc, which ASan has already intercepted, which re-enters ASan's initialiser, which spins forever on a lock it is already holding. Apple's clang, not my code.

What I took away

  • Everyday builds and UBSan: Apple clang. AddressSanitizer: Homebrew clang only. This is now a fixed rule on this machine and it is written down in the toolchain sheet.
  • A hang is evidence, not a dead end. Sampling the process answered in one step what an hour of re-reading my own code would not have.
  • Written up in full, with the stack, as learning record 0001.
