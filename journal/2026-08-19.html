Two builds, and the shape of Project 1

Built

No code yet — this was deciding the shape of the Project 1 repository, which turns out to be a set of decisions I will have to defend rather than a thing I can just do.

  • Header-only. vector and unordered_map are class templates, so there is no code to compile until someone instantiates them. In CMake that is add_library(containers INTERFACE) — a named bundle of include paths and flags that compiles nothing of its own.
  • Two presets, two build directories. dev (Apple clang, UBSan) and asan (Homebrew clang, ASan + UBSan). Separate directories rather than separate flag sets, because CMake caches the compiler per build directory, and object files from two different toolchains must never be linked together. Separate directories make mixing them structurally impossible instead of merely unlikely.
  • -Werror from day one, with -Wall -Wextra -Wpedantic.

What broke

Homebrew's clang could not find <iostream> — it fails with no such sysroot directory. It does not inherit Apple's SDK path the way /usr/bin/clang++ does, so it needs -isysroot $(xcrun --show-sdk-path) passed explicitly. Because a CMake preset is JSON and JSON cannot run a command, that path has to be written out literally in the preset, and it will need regenerating after an Xcode update.
