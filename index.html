Lessons

Written for this tutorial and worked through in order. Each one ends in code I actually compiled and ran on my machine; the commands and their output are real, not illustrative.

  • Lesson 1 — Four Programs, Not One The four separate programs hiding behind one clang++ command: preprocessor, compiler, assembler, linker.
  • Lesson 2 — Two Builds, One Source Tree Why one source tree needs both a debug and a release build, and how to keep the two from fighting.
  • Lesson 3 — The Linker Only Sees What You Listed Undefined symbol errors, and why dropping a .cpp into src/ does not put it in the build.
  • Lesson 4 — CMake Is Not a Build System CMake is a generator, not a build system. What it actually buys you is the dependency graph.
  • Lesson 5 — The Heap, and Your First Vector Stack versus heap, and a forty-line Vector that grows — containing a deliberate leak to find with a tool.
  • Lesson 6 — The Destructor, and the Bug It Creates One function fixes the leak from Lesson 5 — and immediately turns a silent leak into a double free. RAII, and why the destructor is never the whole answer.
  • Recall — Weeks 1–2 Interactive recall over weeks 1–2: the build pipeline, CMake, the heap, and the first Vector.

Learning records

One file per thing that cost me real time to figure out, with the evidence that settled it. These are the ones where the answer was not in any tutorial.

  • Apple clang's AddressSanitizer is unusable on this machine
  • Project 1's build is a header-only INTERFACE library with two presets
  • A .cpp in src/ is not in the build until add_executable names it
  • CMake earns its place through the dependency graph, not through convenience
  • AddressSanitizer reports no leaks on macOS; leaks fills the gap
  • -fsanitize=undefined makes Apple's leaks report zero leaks
  • A heap-corruption abort under the dev preset prints nothing at all
