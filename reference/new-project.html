Starting a New C++ Project

The same five minutes every time you want to try something — a YouTube tutorial, a scratch experiment, a question you want to answer with code. Do not think about it; run the script and start typing C++.

The 30-second version

$ cd ~/projects/cpp-tutorial          # or wherever scratch work lives
$ newcpp cherno-practice
created cherno-practice/
  cd cherno-practice && ./build/cherno-practice
  edit, then: cmake --build build

That already compiled and ran. newcpp lives at ~/.local/bin/newcpp; it is a bash script, and it is meant to be edited when your defaults change.

What it made

cherno-practice/
├── CMakeLists.txt          C++20, -Wall -Wextra -Wpedantic, optional sanitizers
├── .gitignore              build/, .DS_Store, compile_commands.json
├── compile_commands.json → build/…  symlink, so clangd works in your editor
├── include/                empty, ready for headers
├── src/main.cpp            prints "hello"
└── build/                  generated, disposable, never committed

Plus a git repo with one commit, so you can always get back to a working state.

The loop, forever after

You did thisThen run
Edited a .cpp or .hppcmake --build build
Want to run it./build/<name>
Both, in one linecmake --build build && ./build/<name>
Added a new .cppAdd it to add_executable, then cmake --build build
Added a new .hppNothing. Headers are never listed.
Build has gone strangerm -rf build && cmake -B build — always safe
Want to see the real clang++ linescmake --build build -v

Make the two-command line a shell alias if you like. It is the one you type all day.

Turning on sanitizers

A second build directory, so the two never mix. Apple clang's AddressSanitizer hangs at startup on macOS 26, so this needs the Homebrew compiler — the generated CMakeLists.txt warns you if you forget, and adds the -isysroot Homebrew clang needs on its own.

$ cmake -B build-san -DSAN=ON \
      -DCMAKE_CXX_COMPILER=/opt/homebrew/opt/llvm/bin/clang++
$ cmake --build build-san && ./build-san/<name>

Reach for it when something is mysterious, when a crash is intermittent, or before you show code to anyone. Full details in the toolchain sheet.

Following a Windows tutorial on your Mac

Most C++ YouTube — The Cherno included — is Visual Studio on Windows. Nothing about the C++ changes; only the button-pressing does. Translate as you watch:

He saysYou do
“Create a new project”newcpp name
“Hit F5” / “Local Windows Debugger”cmake --build build && ./build/name
“Right-click, Add → New Item”Create the file, then add it to add_executable
“Set the configuration to Release”cmake -B build-rel -DCMAKE_BUILD_TYPE=Release
“This is the solution, this is the project”Solution ≈ the CMakeLists.txt; project ≈ one target
#include "pch.h", stdafx.hSkip it. Visual Studio precompiled headers, not C++.
system("PAUSE"), conio.h, <windows.h>Skip. Windows-only; your terminal does not close on you.
__declspec, WinMainSkip. Not portable C++.
Style warning Video is for intuition; learncpp is for style. Tutorial C++ leans on raw new/delete and pre-C++11 habits. Inside a container that is correct and it is exactly what Project 1 asks for. Outside one it is the habit that gets flagged in review.

When it does not build

MessageAlmost always
Undefined symbols … referenced from x.cpp.oA .cpp is missing from add_executable. It is never the file named in the error.
fatal error: 'foo.hpp' file not foundWrong path in the #include, or the directory is missing from target_include_directories.
No such file or directory: buildYou never configured. cmake -B build.
Editor red-underlines correct codecompile_commands.json is stale or unlinked. Reconfigure; check the symlink exists.
Your edit had no effectYou ran the binary without rebuilding, or you are running a binary from the other build directory.
Sanitizer binary hangs, prints nothingApple clang. Reconfigure with the Homebrew compiler.

Doing it by hand, without the script

Worth doing once so the script is not magic, and needed on any machine that has no newcpp:

mkdir -p proj/src && cd proj
printf '#include <iostream>\nint main(){ std::cout << "hello\\n"; }\n' > src/main.cpp

cat > CMakeLists.txt <<'EOF'
cmake_minimum_required(VERSION 3.28)
project(proj LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)
add_executable(proj src/main.cpp)
target_include_directories(proj PRIVATE include)
target_compile_options(proj PRIVATE -Wall -Wextra -Wpedantic)
EOF

cmake -B build && cmake --build build && ./build/proj

And the smallest thing that works at all, when you just want to check one line of syntax and a project would be overkill:

clang++ -std=c++20 -Wall -Wextra scratch.cpp -o scratch && ./scratch

For a single file with no headers of your own, that is genuinely fine. Reach for a project the moment there are two files, or you want sanitizers, or you want it to survive the afternoon. Or use Compiler Explorer and skip the file entirely.
